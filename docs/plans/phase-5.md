# Phase 5 — Five screens, MVI ViewModels and the Shizuku toolkit (story US-5)

Source spec: `TEMPLATE.md` §5 (screens 1–5), §6 (zero-observer-effect), and §7 Aşama 5 (Turkish). Phases 1–4 are done (`PROGRESS.md`). Data-surface inventory: SQ-63, which maps every §5 element to its producers and gaps at `ea266b5`.

## Outcome
The app becomes the product. There are five top-level screens, each in its own `:feature:*` module with an MVI ViewModel, unit tests and screenshot previews:
1. **Cockpit** (`:feature:dashboard`). It has:
   - reference pill and Shizuku pulse
   - Battery Story
   - live gauge
   - 2×2 metric grid
   - synchronized scrubbing chart; its range brush drives the app-wide time-slice mode
2. **X-Ray** (`:feature:xray`). Components/apps toggle, per-app stacked bars, and an app detail sheet with Shizuku quick actions.
3. **Sleep Lab** (`:feature:sleeplab`). Hypnogram, the wakelock / kernel wakelock / alarm tabs with dictionary explanations, and CPU cluster frequency residency.
4. **Charge & Health** (`:feature:health`). Charge curve, health card (design vs FCC vs measured capacity, cycles), wear chart, and heat/voltage wear analysis.
5. **Toolkit** (`:feature:toolkit`). Doze profiles (experimental), the app background restrictor (appops and standby bucket), force-stop and bg-dexopt. These are the app's first privileged writes.

The template Home placeholder is removed. This phase also wires in the backend pieces that nothing uses in production yet: the analysis chain, LiveTelemetry, the charge pipeline and markers.

## Device facts (orchestrator, API 36 emulator, 2026-10-17; every change reverted)
- **Doze constants.** `device_config put device_idle <key>` fails for shell with `SecurityException: … must add flag to the allowlist`. `settings put global device_idle_constants light_after_inactive_to=120000` takes effect at once: `dumpsys deviceidle` → `Settings:` shows `+2m`. `settings delete global device_idle_constants` restores the default (`+4m`). API 37 and OEM behaviour are unverified, so T2 must prove both emulators, and doze stays verify-after-apply (H11).
- **App ops.** `cmd appops set <pkg> RUN_ANY_IN_BACKGROUND ignore|default` works, and `cmd appops get` reads it back.
- **Standby bucket.** Set with `am set-standby-bucket <pkg> <active|working_set|frequent|rare|restricted>`; read with `am get-standby-bucket` (10/20/30/40/45). The spec's `cmd usagestats set-standby-bucket` returns "Unknown command".
- **Dexopt.** `cmd package bg-dexopt-job` blocks until it finishes. `--cancel` exists.
- **Force idle.** `cmd deviceidle force-idle|unforce` exists, but it is a test hook.
