# Phase 4 — Design system and custom chart components (story US-4)

Source spec: `TEMPLATE.md` §5 (Görsel Dil; Ekran 1 item 5 and Ekran 3 item 1) and §7 Aşama 4 (Turkish). Phase 3 (`docs/plans/phase-3.md`) is complete. Nothing here changes telemetry, diagnostics or persistence.

## Outcome
A new `:core:designsystem` module that every feature module and `:app` consume. It holds:
1. **The Inspiration theme.** AMOLED-black Material 3 Expressive, with a full token set: color roles, semantic telemetry colors, an Inter type scale with tabular figures, shapes, spacing and the Expressive motion scheme.
2. **`SynchronizedScrubbingChart`.** A Canvas timeline with a battery % line, a temperature line and Gantt lanes (screen on, deep sleep, screen-off awake, charging). It has a press-and-hold scrub cursor that reads every series at one instant, and a **range brush** (drag to select a time slice) that the caller hoists. Phase 5 uses the brush to put the app into time-slice mode.
3. **`SleepHypnogram`.** A Canvas step chart of screen-off stages (awake, maintenance, light idle, deep idle) with wake pulses.

The components are data-agnostic. They take immutable chart models, and mapping telemetry onto those models is Phase 5's job.

These are proven by:
- JVM unit tests of all chart math and gesture-state logic.
- Compose preview screenshot references: light, dark, font scale 1.5, width 840, plus selection, cursor and empty states.
- An Opus visual review of the rendered PNGs.
- An orchestrator frame-time measurement on the emulator, using a debug gallery activity with dense synthetic data.

## Design brief
- **Subject:** battery analytics and diagnostics for Android power users, using real system telemetry through Shizuku.
- **Audience and situation:** enthusiasts checking at night or first thing in the morning ("what drained it overnight?"), one-handed, often in a dark room. Glance first, then drill down (§5 Progressive Disclosure: "Oura-simple on top, Perfetto-deep underneath").
- **Memorable element:** the synchronized scrubbing timeline. Dragging across the night's drop turns the whole app into a time slice.
- **What stays quiet:** chrome. No gradients and no shadows. Cards are tonal surfaces with one hairline border. **Color carries data meaning only.** The four semantic hues never decorate, and the brand accent is a neutral "ice" white rather than a fifth hue that would compete with the legend.

| G8 | **Chart math** (pure, `designsystem/chart/math`, JVM-tested): `TimeScale`, `ValueScale`, `niceTimeTicks` (steps 5/10/15/30 min, 1/2/3/6/12 h, 1 d; ≤ `maxTicks`; aligned to local wall-clock boundaries for the given `ZoneId`), `decimateMinMax` (per pixel column, keep min and max in time order and always keep the first and last point; output ≤ 2 × buckets + 2 points), `nearestIndex` (binary search), `normalizeSelection` (orders the ends, clamps to the window, enforces `minDurationMs`, returns null if the window is shorter than the minimum), `valueAt` (linear interpolation between neighbours, null outside the data). Plus a pure **gesture reducer** `ScrubGestureReducer(minSelectionMs: Long, slopPx: Float, handleHitPx: Float)`. States: Idle, Scrubbing(tMs), Brushing(anchorMs, currentMs), DraggingHandle(edge, otherEdgeMs, currentMs). Events carry pointer x in px plus the current `TimeScale`: Down(x), LongPress(x), Move(x), Up(x), Cancel. Down within `handleHitPx` (≥ 48 dp converted) of a selection edge enters handle drag; a move past `slopPx` otherwise enters Brushing. The reducer decides commit, clear and cursor without Compose, so gesture semantics are unit-tested with no ui-test dependency. **A short drag (under slop or under `minSelectionMs`) is a no-op, not a clear**; only a clean tap (Down→Up within slop, no long press) clears an existing selection. | Testable math; no new test dependency. |
| G9 | **SynchronizedScrubbingChart.** Layout from top: a readout row (time and values at the cursor, else the selection span and its battery drop, else the window summary), the line plot (battery % on 0–100 % fixed axis; temperature on its own auto range, right-hand labels), then one 12 dp lane per `Lane` (rounded 4 dp segments in the lane hue), then the time axis. **Gestures:** one `pointerInput` with a single `awaitEachGesture` loop that feeds the G8 reducer. A horizontal drag starting anywhere creates the brush selection (live preview, committed via `onSelectionChange` on Up). A short drag is a no-op (G8). A clean tap clears an existing selection (`onSelectionChange(null)`). Press-and-hold shows the cursor and follows the finger until release (`onScrub(tMs)` / `onScrub(null)`); **after a long press every move is consumed**, so the parent doesn't scroll while scrubbing. Before the slop is crossed nothing is consumed, and a mostly-vertical move hands the gesture to the parent, so vertical scrolling still works. Edge handles have ≥ 48 dp hit targets. The plot area sets `Modifier.systemGestureExclusion` (clipped to ≤ 200 dp height, the platform limit) so a brush starting at the screen edge isn't taken as Back. `pointerInput` is keyed on `data.window` and reads callbacks through `rememberUpdatedState`. **Performance contract:** paths, decimation and tick labels are built in `Modifier.drawWithCache` keyed on data, size, colors and density. The cursor and brush-preview positions are `mutableLongStateOf`/`mutableFloatStateOf` (no boxing) read **only inside the draw lambda**, so a drag frame triggers redraw, not recomposition or relayout **of the plot or the chart's parent**. The readout row is the one composed element that shows live values: it's an isolated child composable that reads the cursor through a `() -> Long?` lambda, so only that child recomposes per frame. No allocation in the per-frame draw path (reuse `Path`s and precomputed arrays). Text is measured with `rememberTextMeasurer` inside the cache block. **Synchronization:** both charts take `cursorMs: () -> Long? = { null }`; the scrubbing chart also reports `onScrub`. A screen holding one `mutableLongStateOf` can drive the hypnogram's cursor line in the draw phase with no recomposition. **Accessibility:** `semantics { contentDescription = window summary; stateDescription = selection summary; customActions = [Clear selection] }`; lanes and legend use `@StringRes` labels; min height 48 dp per touchable region. **Empty state:** a designed empty message ("No history for this window yet", en/tr) when there are no series points and no lane segments. Selection outside: a dim overlay (scrim at 55 % alpha) outside the selected range, edges as 2 dp `primary` lines with 12 dp grab affordances. Dragging a grab handle adjusts that edge (reducer events carry `HandleStart`/`HandleEnd`). | §5 Ekran 1 item 5 ("Range Brush", "Zaman Dilimi Modu"); 120 Hz target means no recomposition per frame. |
| G10 | **SleepHypnogram.** Four rows top to bottom: Awake, Maintenance, Light idle, Deep idle. Each segment is a filled 4 dp-rounded bar on its row (deep `deepSleep`, light `lightSleep`, maintenance `awake` at 70 %, awake `awake`), and consecutive segments are joined by 1 dp vertical connectors in `chartGrid`, giving the hypnogram step look. Wake pulses are 2 dp × 8 dp `critical` ticks above the Awake row. Gaps (no segment) are left empty, not interpolated. Optional `selection: TimeRange?` dims outside the range, and `cursorMs: () -> Long?` draws a cursor line (read in the draw phase), so the hypnogram stays in sync with the scrubbing chart. Shared time axis and drawing helpers (G8 ticks + axis drawer). Row labels at the start (`@StringRes`), tabular duration totals per stage at the end (e.g. "Deep 5 h 12 m"). Empty state as G9. Static: no gestures in Phase 4. | §5 Ekran 3 item 1 (Light Doze, Deep Doze, Maintenance, wake pulses). Data availability is a Phase 5 concern (history today has DEEP_IDLE_ON/OFF but not light idle or maintenance; see Non-goals). |
| G11 | **Base components (minimal):** `MetricValue(value: String, unit: String, modifier, style)` (numeric typography plus a smaller unit, baseline-aligned), `InspirationCard(modifier, onClick?, content)` (surfaceContainer, large shape, 1 dp outlineVariant border, no elevation), `SemanticDot(color)`, and `LegendRow(items)`. | G12 | **Debug gallery:** `app/src/debug/.../debug/DesignGalleryActivity` (exported in the debug manifest only, so `adb shell am start` works). The gallery parses no intent extras. | Measured instead of asserted. |

## Non-goals (owning phase)
- **Phase 5:** mapping history/diffs onto chart models; the time-slice mode itself (re-running diagnostics for a brushed range); screens, navigation, ViewModels; a theme toggle; the live gauge.
- **Hypnogram data:** `history_event` has DEEP_IDLE_ON/OFF (9/10) but no light-idle, maintenance or wake-reason events. Phase 5 decides whether to extend history extraction (batterystats history carries device-idle mode and wake-reason tags) or show only what's measured. Phase 4 components must render partial data (gaps) correctly.
- No new Gradle dependencies (no ui-test, no charting library, no downloadable fonts). The font files are assets.
- No hardware frame-time claims; emulator numbers are a proxy.
