---
description: redroid device memory and leftover Gradle processes
priority: 20
---
- The redroid container (Docker, Android 15 + Shizuku 13.6.0) is the only device: the host has no `/dev/kvm`, so the Android emulator can't run. It is always on and uses about 1.9 GB. A session can't stop it, because Docker needs root. 2 Gradle invocations may run alongside it (android-build).
- adb sees redroid twice: as `emulator-5554` (adb's automatic scan of local port 5555) and, after `adb connect localhost:5555`, as `localhost:5555`. Both are the same container. With both attached, a bare `adb` fails with "more than one device", so always set `ANDROID_SERIAL` (either serial works); if `localhost:5555` is missing, run `adb connect localhost:5555` or use `emulator-5554`.
- Before any adb install, uninstall, pm, input or am command, confirm the device: `adb shell getprop ro.product.model` must print `redroid15_x86_64`. When the user's SSH session forwards port 5037 (`ss -ltnp` shows sshd on 5037), a bare adb reaches the adb server on the user's machine, so both `emulator-5554` and `localhost:5555` are their phone. Reach redroid through a local server instead: `ANDROID_ADB_SERVER_PORT=5038 adb connect localhost:5555`.
- Run Gradle through `bash .claude/scripts/gradle-slot.sh <tasks>` from the checkout or worktree root. It holds one of the host-wide slots in `/tmp/claude-<uid>/gradle-slots`, shared by every session and worktree, then runs `gradle-check.sh`. Don't write a per-session slot wrapper. `GRADLE_SLOTS=1` narrows it to one slot after an OOM.
- Before a whole-project gate, end orphaned `GradleWorkerMain` processes (parent pid 1, left behind by a killed daemon) and Kotlin daemons whose Gradle daemon is gone. On 2026-10-19, before the host had zram, a one-shot gate plus these leftovers got the Gradle daemon OOM-killed twice (`journalctl -k`).
- Match these processes with a bracketed pattern (`pgrep -f '[G]radleWorkerMain'`). A plain `pkill -f GradleWorkerMain` also matches the shell running the command and kills it.
